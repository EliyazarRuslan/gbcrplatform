LA-ide v1 — Architecture Approaches

One-click deploy command center built with Tauri + React/TS

A

Monolith Shell

Single Tauri app that handles everything — UI, pipeline execution, SSH connections, cloud API calls, and state management all in one process.

Pros

  • Simplest to build and debug
  • No inter-process communication overhead
  • Single binary distribution

Cons

  • A stuck SSH or long build blocks the UI
  • Harder to extend later (editor, terminal, etc.)
  • All-or-nothing restarts
B

Core + Agent Architecture

Tauri UI shell talks to a lightweight local agent daemon (Rust or Node) that runs pipelines in the background. Agents handle SSH, cloud APIs, and build commands. UI stays responsive.

Pros

  • UI never blocks — agent runs pipelines independently
  • Agent can run headless (CLI / scheduled deploys)
  • Clean separation: UI = display, Agent = execution
  • Natural path to add editor/terminal in v2

Cons

  • Slightly more complex initial setup (IPC between UI and agent)
  • Two processes to manage
C

Plugin-based Extensible

Full plugin architecture from day 1 — each deploy target (Azure, SSH, Vercel) is a plugin. Core provides pipeline engine, UI framework, and plugin API.

Pros

  • Most extensible — easy to add new deploy targets
  • Clean separation of concerns
  • Could open to community later

Cons

  • Over-engineered for v1 with 4-8 projects
  • Plugin API design is hard to get right upfront
  • Slowest to ship

Recommendation: B — Core + Agent

Best balance of simplicity and future-proofing. The agent daemon gives you non-blocking pipeline execution, CLI access for automation, and a clean boundary to bolt on editor/terminal features in v2. Not over-engineered like C, not limiting like A.
