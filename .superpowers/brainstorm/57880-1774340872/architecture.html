Architecture Overview

GBCR Mobile — Monorepo with Expo + Shared Packages

Monorepo Structure
gbcr-platform/
├── apps/
├── web/ ← existing Next.js app (moved from root)
└── mobile/ ← new Expo app
├── packages/
├── shared/ ← TypeScript types, API client, utils
└── api-client/ ← typed HTTP client for all endpoints
├── turbo.json ← Turborepo config
└── package.json ← workspace root

Key Decisions

  • Mobile consumes existing API — no new backend needed, just some new endpoints for push token registration and offline sync
  • Shared package for TypeScript types extracted from current src/lib/types.ts and src/types/
  • SQLite (expo-sqlite) for offline inspection storage
  • Expo Push Notifications via EAS for cross-platform push
  • Socket.io client reused from web app for real-time updates
