Technical Design Details

Offline sync, push notifications, and key libraries

Offline Inspection Sync Flow
1
Inspector fills out form
Photos, damage marks, signatures, readings — all captured natively
2
Saved to local SQLite (encrypted)
Inspection data + photos stored locally with status: pending_sync. A client-generated UUID is assigned to each inspection before first sync. The local SQLite DB is opened with SQLCipher encryption; the DB key is derived from the device keychain (iOS Keychain / Android Keystore) and never stored in plaintext. Photos saved alongside records are AES-encrypted at rest using the same derived key.
3
Network available?
NetInfo API detects connectivity. If online → sync immediately. If offline → queue for later.
4
Background sync (expo-task-manager)
expo-task-manager runs the sync task when connectivity returns. Each inspection is identified by a client-generated UUID included in the sync payload; the server deduplicates by UUID so retries never create duplicates. Photos reference the same UUID to tie assets to the idempotent upload.
  • Retry policy: max 5 attempts with exponential backoff (1 s, 2 s, 4 s, 8 s, 16 s). Respects battery-saver mode and network type (WiFi preferred) before retrying. After 5 failures the inspection is marked “failed” and a manual retry action is surfaced in the UI.
  • iOS 30 s limit: iOS background fetch windows are ~30 s and system-controlled (not on-demand). Large photo batches risk being cut off. Mitigation: upload metadata first, then photos in chunks; use resumable uploads with checkpoints; batch no more than a few photos per task window; fall back to prompting the user to keep the app foregrounded for large uploads.
  • Batching: processes inspections in bounded pages (max 50 per pass) to avoid OOM; uploads inspection data before photos per item.
5
Status updated
Local record marked synced. Inspector sees green checkmark in the offline queue screen.

New API Endpoints Needed

  • POST /api/push/register — Register device push token. Auth required (Bearer JWT). Token must belong to the authenticated user.
  • DELETE /api/push/unregister — Remove push token on logout. Auth required (Bearer JWT). Users may only unregister their own tokens.
  • POST /api/inspections/sync — Batch upload offline inspections. Auth required (Bearer JWT).
    • Batch limits: MAX_INSPECTIONS_PER_BATCH = 50; MAX_SYNC_REQUEST_BYTES = 10 MB. Returns HTTP 413 if exceeded. Clients must paginate large syncs.
    • Idempotency: each inspection must include a client-generated client_uuid. The server deduplicates by (user_id, client_uuid); duplicate submissions return the original server_id without re-inserting.
    • Conflict resolution — Pure last-write-wins: Clients include updated_at in each item. The server always applies the incoming data unconditionally (no version comparison), then returns the authoritative updated_at that was stored. HTTP 409 is never returned for conflicts — it is only used for authentication/authorisation errors or malformed requests. Per-item result shape: { local_id, status: "synced"|"failed", server_id?, authoritative_updated_at?, error? }. On status: "synced" the client should overwrite its local updated_at with the returned authoritative_updated_at to stay in sync with the server. On status: "failed" the item should be retried (respecting the 5-attempt backoff). There is no status: "conflict".
    • Authorization: inspector_id is always set to the authenticated user’s ID — client-supplied value is ignored. Returns HTTP 401/403 for invalid/expired tokens.
  • POST /api/inspections/photos/upload — Multipart photo upload (mobile-optimised). Auth required (Bearer JWT). Users may only upload photos for their own inspections.
    • Validation: maxFileSize = 10 MB per file; maxPhotosPerRequest = 20; allowed MIME types: image/jpeg, image/png, image/heic. Returns HTTP 400 for wrong type, HTTP 413 for oversized files.
    • Processing: files are streamed to OneDrive — not buffered into memory — to prevent OOM on large or concurrent uploads. A per-request timeout/cancellation is applied.
    • Client guidance: compress images client-side before upload (target ≤ 2 MB). Photos reference the same client_uuid as the parent inspection for idempotent linking.

Auth scheme for all endpoints: Bearer JWT in Authorization header (or session cookie for web). Token refresh window: 2 hours before expiry. Expired/invalid tokens return HTTP 401 with { success: false, error: "Unauthorized" }; forbidden actions return HTTP 403.
